concept

use — importer du code externe

En Rust, use sert à rendre disponible du code depuis une autre bibliothèque (appelée "crate"). C'est l'équivalent de import en JavaScript.

// Ton code
use serde::{Serialize, Deserialize};
use std::path::Path;
use walkdir::WalkDir;
use std::process::Command;
use reqwest::blocking::Client;
// Équivalent JavaScript :
import { Serialize, Deserialize } from "serde";
import { Path } from "std/path";
import { WalkDir } from "walkdir";
syntaxe rust

Les accolades dans use

use serde::{Serialize, Deserialize} importe deux éléments d'un coup depuis serde. Sans accolades, on n'importe qu'un seul élément.

// Importer plusieurs en une ligne
use serde::{Serialize, Deserialize};

// Équivalent en deux lignes
use serde::Serialize;
use serde::Deserialize;

concept

struct — définir un type de données

Une struct est un objet avec des champs nommés. C'est comme un objet JavaScript, mais le type de chaque champ est obligatoire.

// Ton code Rust
#[derive(Serialize, Clone)]
struct SearchResult {
    reply: String,
    files: Vec<FileItem>,
}

// Équivalent JavaScript
const searchResult = {
    reply: "",      // String
    files: [],      // Array<FileItem>
};
attributs derive

#[derive(...)] — ajouter des capacités automatiquement

Ces annotations au-dessus d'une struct disent au compilateur de générer automatiquement du code.

#[derive(Serialize, Clone)]
//        ↑           ↑
//   → peut être     → peut être
//   converti en     copié en mémoire
//   JSON
#[derive(Serialize, Deserialize, Clone)]
//   → peut aussi être lu depuis du JSON

fn — déclarer une fonction

Toute fonction commence par fn. Le type de retour est indiqué après ->. S'il n'y a pas de ->, la fonction ne retourne rien.

// Rust
fn search_files(query: String, paths: Vec<String>) -> SearchResult {
    // ...
}

// JavaScript équivalent
function searchFiles(query, paths) {
    // ...
    return searchResult;
}
let et mut

Les variables : immuables par défaut

En Rust, une variable créée avec let est immuable par défaut. Pour pouvoir la modifier, il faut ajouter mut.

let score = 0;        // ❌ ne peut pas changer
let mut score = 0;    // ✅ peut changer
score += 10;          // OK car mut
// Dans ton code
let mut results: Vec<FileItem> = vec![];
// → on va ajouter des éléments donc mut obligatoire
la dernière expression

Retour implicite — pas de return obligatoire

En Rust, la dernière expression d'une fonction est automatiquement retournée si elle n'a pas de point-virgule.

// Avec return explicite
fn double(x: i32) -> i32 {
    return x * 2;
}

// Style Rust idiomatique (sans return)
fn double(x: i32) -> i32 {
    x * 2   // ← pas de ; → c'est la valeur retournée
}
// Dans ton code
OllamaStatus {     // ← retour implicite de la struct
    installed,
    running,
    models,
}                  // ← pas de ;

concept clé de Rust

Ownership — la propriété de la mémoire

C'est le concept le plus unique de Rust. Chaque valeur a un seul propriétaire. Quand ce propriétaire disparaît, la mémoire est libérée automatiquement.

let a = String::from("bonjour");
let b = a;   // a n'existe plus ! b est le nouveau propriétaire
println!("{}", a);  // ❌ ERREUR de compilation

clone

.clone() — faire une vraie copie

Quand on ne peut pas emprunter et qu'on a besoin de la valeur à deux endroits, on clone.

into_iter / collect

Itérateurs — transformer des collections

Rust utilise des chaînes d'itérateurs plutôt que des boucles for classiques. C'est comme les méthodes de tableau JavaScript.

// Rust
let keywords: Vec<String> = query
    .to_lowercase()           // met en minuscules
    .split_whitespace()       // découpe en mots
    .filter(|w| ...)          // garde certains mots
    .map(|s| s.to_string())   // convertit chaque mot
    .collect();               // reconstitue le Vec

// JavaScript équivalent
const keywords = query
    .toLowerCase()
    .split(/\s+/)
    .filter(w => ...)
    .map(s => s);
concept

Result et Option — pas d'exceptions en Rust

Rust n'a pas de try/catch. Les erreurs sont des valeurs retournées. Result représente succès ou erreur, Option représente présence ou absence.

// Result<T, E> : soit Ok(valeur), soit Err(erreur)
let response = client.post(...).send();
// → Result<Response, Error>

// Option<T> : soit Some(valeur), soit None
let ext = path.extension();
// → Option<&OsStr>
match

match — gérer tous les cas

match est comme un switch mais exhaustif : le compilateur oblige à gérer tous les cas.

// Dans ton code
match resp {
    Ok(r) => {
        // succès : r contient la réponse
        let json = r.json()...
    }
    Err(_) => vec![],  // erreur : on retourne un tableau vide
}

// Équivalent JavaScript (try/catch)
try {
    const r = await fetch(...)
    // succès
} catch(e) {
    return [];
}
unwrap_or / unwrap_or_default

Raccourcis pour Option et Result

// unwrap_or → valeur par défaut si None ou Err
path.extension()
    .and_then(|e| e.to_str())
    .unwrap_or("file")   // si None → "file"

// unwrap_or_default → valeur vide du type
r.json().unwrap_or_default()  // si erreur → serde_json::Value::Null
let Ok(...) else

Le pattern "early return" de ton code

C'est un raccourci moderne pour quitter une fonction si quelque chose échoue.

// Dans ton code
let Ok(response) = response else {
    println!("Ollama inaccessible");
    return files;   // ← quitte la fonction ici
};
// ici, on est certain que response est Ok

// Équivalent verbeux
let response = match response {
    Ok(r) => r,
    Err(_) => {
        println!("Ollama inaccessible");
        return files;
    }
};
Tauri

#[tauri::command] — exposer une fonction au frontend

Cette annotation transforme une fonction Rust normale en commande appelable depuis JavaScript avec invoke().

// Rust — côté backend
#[tauri::command]
fn search_files(query: String, paths: Vec<String>) -> SearchResult {
    // ...
}

// JavaScript — côté frontend
const data = await invoke("search_files", {
    query: "mes factures",
    paths: ["/home/user/documents"]
});
invoke_handler

Enregistrer les commandes dans run()

Chaque commande doit être déclarée dans invoke_handler pour être accessible. Oublier une commande = erreur au runtime.

    pull_model

spawn vs output

Lancer un processus : spawn vs output

// .spawn() → lance et n'attend pas la fin
Command::new("ollama")
    .arg("serve")
    .spawn()   // démarre ollama en arrière-plan
    .is_ok()

// .output() → lance et attend le résultat
Command::new("ollama")
    .arg("--version")
    .output()   // attend la réponse
    .is_ok()
